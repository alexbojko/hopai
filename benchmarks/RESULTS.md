## 04 — Findings

**Where the library layer costs most.** `Q12` (AND(OR(...), {...})) ran 5.3x the raw statement (59.9 ms vs 11.2 ms) over 5,400 nodes. The gap is result mapping and property hydration, and it is roughly fixed per call -- so it dominates a small answer and shrinks against a large one. Read it next to the row count, never alone.

**Queries that measured nothing.** `Forward 1-hop, equality` returned zero rows. Finding nothing is always fast, so these timings describe the dataset, not the engine.

Every timing is wall-clock around actual query execution. Warm figures are the median of 5 runs with the cache primed; cold is the first run after load. Queries exceeding the per-query budget are cancelled by the server and reported as DNF, never as a large number.

Synthetic data: a sparse random background DAG plus a deliberately structured hub subgraph with real fan-in across several depth levels — the shape that stresses a traversal engine, which a purely random graph does not.
