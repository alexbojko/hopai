## 05 — Findings

**Where the library layer costs most.** `Q12` (AND(OR(...), {...})) ran 5.3x the raw statement (60.7 ms vs 11.5 ms) over 5,400 nodes. The gap is result mapping and property hydration, and it is roughly fixed per call -- so it dominates a small answer and shrinks against a large one. Read it next to the row count, never alone.

**What aggregating instead of traversing saves.** `Q27` runs `Q14`'s chain and returns a number instead of a subgraph: 56.7 ms against 308.1 ms, **5.4x**. Same walk, same match set -- the difference is the edge-reconstruction CTEs and the property hydration that a count does not need. Pairs measured: `Q19`/`Q3` 1.4x, `Q25`/`Q5` 1.3x, `Q26`/`Q7` 1.3x, `Q27`/`Q14` 5.4x.

**Answers that disagree.** `Q6` hopai 1 vs Neo4j 0; `Q6` hopai 1 vs AGE 0. A speed comparison between systems returning different results is not a comparison -- these are flagged rather than smoothed over, and are worth resolving before quoting the timings beside them.

**Where the alternatives fall over.** `Q4` (Backward bounded <=3 hops) took 47,953 ms on AGE against 14.8 ms here -- 3,240x. Traversal is where the gap opens; plain property filters are competitive on every system.

**Queries that measured nothing.** `Q1`, `Q18`, `Q20`, `Q23`, `Q24` returned zero rows. Finding nothing is always fast, so these timings describe the dataset, not the engine.

**Noisy measurements.** `Q4`, `Q11`, `Q13`, `Q15`, `Q16`, `Q20` varied by more than 50% between warm runs. Their medians are not comparable across commits; re-run on a quiet machine before drawing a conclusion from them.
