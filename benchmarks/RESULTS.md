## 05 — Findings

**Where the library layer costs most.** `Q10` (GT range comparison) ran 6.1x the raw statement (66.4 ms vs 10.9 ms) over 3,780 nodes. The gap is result mapping and property hydration, and it is roughly fixed per call -- so it dominates a small answer and shrinks against a large one. Read it next to the row count, never alone.

**What aggregating instead of traversing saves.** `Q27` runs `Q14`'s chain and returns a number instead of a subgraph: 51.3 ms against 405.5 ms, **7.9x**. Same walk, same match set -- the difference is the edge-reconstruction CTEs and the property hydration that a count does not need. Pairs measured: `Q19`/`Q3` 6.2x, `Q25`/`Q5` 5.7x, `Q26`/`Q7` 5.9x, `Q27`/`Q14` 7.9x.

**Answers that disagree.** `Q6` hopai 1 vs Neo4j 0; `Q6` hopai 1 vs AGE 0. A speed comparison between systems returning different results is not a comparison -- these are flagged rather than smoothed over, and are worth resolving before quoting the timings beside them.

**Where the alternatives fall over.** `Q14` (Deep bounded backward <=12) took 45,047 ms on AGE against 405.5 ms here -- 111x. Traversal is where the gap opens; plain property filters are competitive on every system.

**Queries that measured nothing.** `Q1`, `Q18`, `Q20`, `Q23`, `Q24` returned zero rows. Finding nothing is always fast, so these timings describe the dataset, not the engine.

**Noisy measurements.** `Q2`, `Q6`, `Q10`, `Q12`, `Q20` varied by more than 50% between warm runs. Their medians are not comparable across commits; re-run on a quiet machine before drawing a conclusion from them.
